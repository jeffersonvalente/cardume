# Contributing to Cardume

Contributions are welcome: new skills and agents, fixes, eval cases and docs. This page explains how
the repository is laid out, the conventions a change has to follow, and what the validator checks
before a pull request can merge.

## Layout

```text
cardume/
├── .claude-plugin/marketplace.json
├── skills.sh.json            # where the skills live (for other tools)
├── plugins/cardume-<plugin>/
│   ├── .claude-plugin/plugin.json
│   ├── agents/*.md           # agents (name, description, tools, model, skills)
│   ├── skills/<skill>/       # SKILL.md + references + scripts/ (manual command = disable-model-invocation)
│   ├── hooks/                # (core) hooks.json + scripts
│   ├── evals/<case>/         # prompt.md + graders/
│   └── bin/cardume-*         # generated by scripts/gen_bins.py
├── scripts/
│   ├── validate.py           # suite standards (run in CI)
│   ├── gen_bins.py           # generates the cardume-* commands
│   └── gen_architecture.py   # generates the README diagram (docs/assets/architecture-*.svg)
└── docs/
```

## Making a change

1. Put the agent or skill in the plugin that owns its domain. Each name exists in exactly one
   plugin.
2. Write descriptions in the third person, with a "Use when …" trigger. Keep `SKILL.md` at 500 lines
   or fewer; detail goes into reference files. Write calm instructions that give the reason, without
   MANDATORY/NEVER. [docs/CREATING_SKILLS.md](docs/CREATING_SKILLS.md) covers skill writing in depth.
3. Every agent has a `## Reporting back` section, which returns a requested analysis, plan, review
   or document in full, and the subagent rule (questions go under **Open questions**).
4. New Python script under `skills/*/scripts/`: run `python scripts/gen_bins.py` to regenerate the
   `cardume-*` launchers.
5. New model-invoked skill: add a case in `evals/` (see [docs/EVALS.md](docs/EVALS.md)).
6. Add an entry to [docs/CHANGELOG.md](docs/CHANGELOG.md), bump the version of the plugins you
   changed, and run:

   ```bash
   python3 -I scripts/validate.py
   claude plugin validate . --strict
   ```

If you add, remove or reclassify an agent or skill, update the counts sentence in both
[README.md](README.md) and [README.pt-BR.md](README.pt-BR.md), and the
[catalog](docs/CATALOG.md).

## What the validator blocks

`scripts/validate.py` runs 21 checks on every pull request. It blocks:

- **Identity:** names of clients, companies or people (a hashed list; get the hash for a new name
  with `python scripts/validate.py --hash <name>`), update or phone-home hosts, and legacy
  placeholders. Commit messages go through the same name check in CI.
- **Structure:**
  - every skill folder has a `SKILL.md`, with valid frontmatter that uses only keys Claude Code
    understands;
  - names are unique and follow the Agent Skills format;
  - `SKILL.md` is at most 500 lines;
  - model-invoked descriptions have a trigger;
  - the skill listing fits 14,000 characters and agent descriptions fit 12,000, which leaves room
    for other plugins.
- **Consistency:**
  - every `cardume-<plugin>:<name>` reference exists;
  - no `@[...]` pseudo-references;
  - agents do not preload manual-only skills;
  - every agent has the subagent rule and returns analyses, plans, reviews and documents in full;
  - every agent appears in the routing table;
  - hooks point to scripts that exist;
  - `guard_bash` asks for each risky command in its list and stays quiet on reads and dry runs;
  - eval cases list their plugin and its dependencies, regex graders use `flags: i` instead of
    `(?i)`, and every named scaffold script exists;
  - the counts sentence in `README.md` and `README.pt-BR.md` matches the files;
  - `docs/CHANGELOG.md` changes whenever `plugins/` changes.

CI also checks that the `bin/` launchers are up to date and runs
`claude plugin validate . --strict` on the manifests.
