# Changelog

All notable changes to Cardume are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed
- Evals of the plugins that depend on `cardume-core` ran without the plugin loaded: the dependency was
  missing, so the plugin did not load and both arms were plain Claude. Every case now lists its plugin
  and its dependencies, and evals run from `plugins/` with `--eval-dir` (#2).
- Eight regex graders used inline `(?i)`, which JavaScript regex doesn't support; they use `flags: i`.
- Three cases that point at a project file now create it with a `scaffold_script`.
- `guard_bash` no longer takes `-n` as a dry run outside `git push` and `cargo publish`: for `helm` it is
  the namespace, for `gh release` the notes, for `poetry` and `twine` non-interactive mode. Those commands
  ran without asking. A dry-run flag now counts only for the command it is on, not for the whole line, a quoted note or a
  comment, and backslash line continuations are followed.
- `guard_bash` no longer asks for `kubectl` reads that mention a verb, such as `kubectl get pod delete-me`
  or `kubectl auth can-i delete pods`.

### Added
- `docs/CONFIGURATION.md` explains running Cardume alongside other plugins: how the skill listing budget
  works, how to spot an overflow, and how to fix it on a 200k context window.
- `routing_reminder` hook: before each request, reminds Claude to state the work level, use the matching
  skill or agent and name it in one line, with process skills first (`CARDUME_ROUTING_NUDGE=0` turns it off).
- `guard_bash` asks before `kubectl` commands that change a live cluster and before `helm install` and
  `helm upgrade`. Recognized `kubectl` and `helm` reads, and their dry runs, pass without asking; a line it
  can't parse asks.
- Validator checks (now 21): eval cases must list their plugin and dependencies, regex graders can't
  use `(?i)`, and named scaffold scripts must exist; `guard_bash` runs against commands that must ask
  and commands that must pass; every agent must return deliverables in full.
- Team rollout: a committed `.claude/settings.json` installs Cardume for everyone who opens the
  repository, and managed settings can require it across an organization (README and
  `docs/CONFIGURATION.md`).

### Changed
- Agents return the full text when the request is an analysis, plan, review or document. The ~250-word
  limit now applies only to reports on executed work: it was cutting deliverables down to a summary.
- Skill descriptions are about 45% shorter, with the trigger stated plainly and no lists of contents. The
  listing drops from about 19,800 to about 12,000 characters.
- The description ceiling in the validator counts what Claude Code really lists: 14,000 characters for the
  skill listing, with each `plugin:name` prefix, and 12,000 for agent descriptions, instead of 32,000 for
  both together.
- README rewritten in English, opening with what Cardume adds (a specialist for each part of the job,
  a process sized to each change, hooks the model cannot skip) instead of counts; a Brazilian
  Portuguese mirror is in `README.pt-BR.md`.
- New "What you can hand it" section: sample requests from every area and the agent that picks each up.
- Architecture diagram as light/dark SVGs generated by `scripts/gen_architecture.py`.
- Three side-by-side recordings in `docs/assets/`, the same request with and without Cardume: a level-2
  feature (spec skill, decisions, approval before code), a Terraform review routed to `iac-reviewer`,
  and a force push stopped by the guard hook.
- Reference material moved out of the README into English docs: `docs/HOW_IT_WORKS.md`,
  `docs/SAFETY.md`, `docs/CONFIGURATION.md` (now also covering other tools, replacing
  `docs/OUTRAS_FERRAMENTAS.md`), `docs/EVALS.md`, `docs/CATALOG.md` (every agent, skill and manual
  command) and `CONTRIBUTING.md`.
- The validator's counts check now reads the English sentence in `README.md` and the Portuguese one
  in `README.pt-BR.md`.
- Marketplace and plugin descriptions are now in English.

## [2.0.0] - 2026-10-28

First public release.

### Added
- Seven Claude Code plugins in the `cardume` marketplace (`cardume-core`, `-frontend`, `-backend`,
  `-data`, `-platform`, `-qa`, `-games`) plus the `cardume-all` bundle: 33 agents, 62 skills and
  13 user-invoked commands.
- Proportional spec-driven delivery: work levels 0–3 classified automatically; `spec` → `tasks` →
  `implement` → `verify` → `review` for features; PRD → architecture → gate → release for products,
  with ADRs (MADR) at any level and an independent `qa-gatekeeper`.
- Hooks: syntax check after edits, security scan + lint on changed files before a turn ends,
  confirmation before destructive or public commands, write limits for the verifier, and a
  reminder for large changes without a spec or ADR.
- Safe project setup (`cardume-setup-project`): only a marked block of `CLAUDE.md` changes, with
  backups; `AGENTS.md` is imported, never written.
- `claude plugin eval` suites for every plugin and a CI workflow; a repository validator with
  18 checks.
- Skills follow the open Agent Skills format and can be installed in other tools.
